# internship-task-multiagent
Мультиагентная система анализа карьерного рынка IT

---

## Пара слов об отчётах

- В папке `example` лежат результаты работы при использовании основной модели `yandexgpt-5.1/latest`.
- В папке `other_example` лежат результаты работ альтернативных моделей.

---

## Запуск

```bash
python main.py --role "<Название специальности>" --out "<Директория>"
```

**Параметры запуска:**
* `--role`: (Обязательно) Название специальности (например, "Data Scientist" или "DevOps Engineer").
* `--out`: (По умолчанию: `examples`) Директория, в которую будут сохранены логи и итоговые отчёты.

**Примеры:**
* `python main.py --role "Data Scientist"`
* `python main.py --role "DevOps Engineer"`
* `python main.py --role "iOS Developer (Swift)" --out "./iOS Developer (Swift)"`

**Результат:** В папке `examples/` (или указанной в `--out`) появятся логи, а также файлы `report.json` и `report.md` с полным разбором.

## Настройка

1.  **Зависимости:**
    ```bash
    pip install -r requirements.txt
    ```
2.  **Окружение:**
    Создайте файл `.env` на основе примера и добавьте ключи:
    ```env
    # Yandex Cloud (Основная модель)
    YANDEX_CLOUD_API_KEY=your_key
    YANDEX_CLOUD_FOLDER=your_folder_id
    
    # Gemini API (Опционально, если захотите поменять "мозги" у агента)
    GEMINI_API_KEY=your_gemini_api_key
    PROXY_URL=http://username:password@host:port
    ```

## Выбор LLM
В текущей реализации все агенты используют в качестве модели `yandexgpt-5.1/latest`.
Эта модель показывает достаточно хороший результат и, в отличие от зарубежных аналогов,
выдаёт наиболее реалистичные зарплатные вилки для российского рынка.

**Другие протестированные модели:**
- `gemini-3.1-pro-preview`: показывает лучшие результаты во всём (особенно эффективна в роли Агента-критика), кроме зарплат. Но в связи с меньшей доступностью модели `gemini-3.1-pro-preview` приоритет был отдан `yandexgpt-5.1/latest`. При этом в коде осталась возможность без проблем сменить модель у агента на `gemini-3.1-pro-preview`.

- `qwen3-235b-a22b-fp8/latest`: не показала значимых преимуществ при более высоких требованиях к ресурсам.
 
- `gpt-oss-120b/latest`: при высоких системных требованиях качество ответов и следование инструкциям оказалось ниже, чем у конкурентов. К тому же критик всё незаслуженно забраковал.

**P. S.** Возможно, было бы хорошей идеей использовать для всех агентов, кроме критика, `yandexgpt-5.1/latest`, а для критика — `gemini-3.1-pro-preview`. Но у меня закончилась квота, чтобы это проверить.

**WebSearch:**
Я также пытался использовать встроенный инструмент от OpenAI для добавления агентам возможности поиска, но за повышение качества пришлось заплатить стабильностью: контекст порой выходил за пределы допустимого количества токенов. В текущем релизе акцент сделан на надёжность, поэтому поиск отключён.

## Архитектура агентов

Система состоит из 4 агентов, работающих в цепочке. Все агенты находятся в пакете `agent` и используют для обращения к модели метод из файла `llm_provider`.

### 1. Market Analyst (Аналитик)
Разбивает профессию на карту навыков:
* **Стек:** Языки, фреймворки, инфраструктура.
* **Приоритет:** `critical` / `important` / `nice-to-have`.
* **Тренд навыка:** Насколько технология/навык актуальны: `growing` / `stable` / `declining`.

### 2. Salary Estimator (Оценщик)
Считает деньги и ищет работу:
* **Таблица:** Зарплаты по грейдам `Junior` / `Middle` / `Senior` / `Lead` и локациям `МСК` / `Регионы` / `Remote USD`. Для каждой ячейки — три числа: min, median, max (тыс. руб. или USD для удалёнки).
* **Работодатели:** Список реальных лучших компаний для этого стека.
* **Тренды на рынке:** `growing` / `stable` / `declining` + краткое обоснование тренда.

### 3. Career Advisor (Ментор)
Составляет путь развития:
* **План, разделённый на фазы:** Пошаговое обучение на 90 дней (3 фазы по 30 дней).
* **portfolio_project:** Финальный подробно разобранный проект, подтверждающий знания.

В каждой фазе:
* **Ресурсы:** Конкретные названия документаций, книг или курсов.
* **Ожидаемый milestone:** Идея детального проекта для портфолио.

### 4. Quality Verifier (Критик)
Проводит технический аудит всего отчёта:
* **Валидация:** Проверка на галлюцинации и логические дыры.
* **Вердикт:** Выставляет `quality_score` (0–100) и показывает недочёты/ошибки в `warnings`.
* **Обоснование вердикта:** Причины выставления такого `quality_score`.
